# Проецируемый свет: перенос и проверка

Срез 2026-11-19. Начало расследования — снимок телефона в тире с обрезанным по полигонам пятном света. Старый `CL_UpdateFlashlight` создавал общий аналитический конус, записываемый в редкую сетку BSP lightmap. В оригинале источники отличаются, а свет рисуется отдельным проходом с проецируемой цветной текстурой. Это доказанное расхождение кода; принадлежность каждого дефектного пикселя на пользовательском снимке конкретной ветке не измерялась.

## Навигация

- Оригинальные параметры, attachments, texgen, стадии света: `flashlight-native-followup.md/.json`.
- Все найденные текстовые программы и их хэши: `shader-coverage.md/.json`.
- Вызовы, samplers, матрицы, bump/specular/blur и порядок проходов: `shader-pass-contracts.md/.json`.
- Серверные состояния и сообщение `CofLight`: `src/cof/server/cof_special.cpp`.
- Передача attachments и направления: `src/cof/client/cof_weapons_client.cpp`.
- Создание отдельных источников: `src/cof/render/cof_attached_lights.inc`.
- Получатель OpenGL: `src/cof/render/gl_cof_projected.c`, `shaders/projected.vert/.frag`.
- Подготовка disposable engine: `tools/prepare_attached_lights.py`, `tools/prepare_projected_lights.py`. Оригинальные ресурсы и `external/` не изменяются.

## Что изменилось

Телефон, ручной фонарь и Glock получают отдельные идентификаторы, радиус700, исходные FOV и текстуры. Phone/torch увеличивают FOV50 до80 при приближении к стене с восстановленным плавным переходом; tactical сохраняет70. Позиции и направления берутся из восстановленных attachment-контрактов. Если модель ещё не дала корректные attachments, временно используется позиция глаз; это явно ограниченный адаптер запуска кадра. RGB поля оригинальных записей сохраняются как данные, но **не умножаются на цвет проекции**: исследованный native world receiver их не использует.

В обычном режиме свет рассчитывается на фрагменте геометрии с GL_EQUAL, без записи глубины, с исходными цветными `gfx/flashlight.tga`/`flashlight2.tga`. Локальные координаты движущегося brush учитываются. Старый сферический/светокарточный вклад этих источников исключён. Прозрачные отверстия учитываются по alpha исходной текстуры. Лицевая сторона, направление V проекции, квадратичное затухание и Lambert согласованы с разобранными стадиями. Поскольку исходный конечный проход применяет `DST_COLOR,SRC_COLOR`, вклад поверх уже нарисованного Xash diffuse равен `2*albedo*cookie*attenuation*incidence`.

При включённом `gl_bump` динамический проход читает исходные `gfx/bumpmaps/<material>.tga`. Базис соответствует конструктору оригинала: отдельно нормализованные S/T текстуры и ориентированная нормаль плоскости. Нормализуется направление света в этом базисе; декодированная нормаль `2*RGB-1` повторно не нормализуется. Если карты нет, используется плоская нормаль. Ограниченный кеш запоминает также отсутствующие карты; собственные текстуры освобождаются при смене уровня, заимствованные handles не удаляются. Это перенос динамического bump-света, а не статических bump/specular-проходов.

`CofLight` — собственный однобайтный протокол: маска 1 — phone, 2 — torch, 4 — tactical; допускается комбинация двух рук. Значение128 обозначает старый engine impulse100. Короткий/неизвестный пакет отвергается. Состояние восстанавливается при синхронизации HUD и периодически повторяется; это не копирование закрытого x86 layout. Дополнительные поля engine `dlight_t` находятся после публичного SDK prefix, engine и renderer собираются совместно.

RTX передаёт разные источники в RTGL1 с их направлениями/FOV и стабильными идентификаторами. API прожектора RTGL1 не принимает исходную cookie-текстуру: используется её центральный цвет и относительный пик. Его физическое затухание и форма конуса остаются адаптацией, а не точной копией обычного CoF. Нельзя описывать эту ветку как восстановленный native shader.

## Проверка

Сборка Waf. Команды:

```
python tools/smoke_rtx.py --renderer normal --projected --timeout 100
python tools/smoke_rtx.py --renderer rtx --projected --timeout 100
python tools/smoke_rtx.py --renderer normal --weapons --timeout 100
python tools/smoke_rtx.py --renderer rtx --weapons --timeout 100
```

Каждый запуск использует отдельный Windows desktop и `-nosound`. Новый `--projected` проходит phone → torch → tactical → phone+tactical → off. Проверяются реальные engine/renderer границы. В normal дополнительно выполняется production GLSL в отдельном FBO с `glReadPixels`: 15 проверок, включая стык полигонов, затухание, обратную сторону, предел проекции, alpha-отверстие, реальные цветные маски, ориентацию V, угол падения, наклон/длину нормали и неортогональный базис. На `c_sdkmap1` подтверждена загрузка authored normal map материала `c2_subccrete3`. Это проверка вычисленных пикселей шейдера, **не сравнение сцены с оригинальной игрой**. Итоговые результаты и хэши сохраняются в `projected-light-verification.json`.

## Границы

Полная графика CoF ещё не восстановлена. Независимые статические diffuse/bump atlases, низкие/высокие specular passes, blur и studio lighting имеют отдельные контракты в справочнике и не считаются реализованными по факту извлечения программы. Проекция на studio-треугольники, смешанная полупрозрачность, conveyor UV, native fog interaction и тени требуют отдельного переноса/сравнения. Старые reduced/low-flashlight режимы и сетевые player-extra light flags не приравниваются к текущим трём источникам. Аналитическое затухание сохраняет формулу, но не дискретизацию старой 256-элементной 1D-текстуры.
