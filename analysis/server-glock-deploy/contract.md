# Glock: извлечение, убирание, фонарик и общий Deploy

Статический pass28 оригинального server `hl.dll`, SHA256 `751a68831e4fe3541bbbb24da3c785fb9f6cd3d7e6dcd92125fe1e18f0fce641`. Пять новых функций и полное уточнение существующей `1011c1a0`. Игра не запускалась. Полные saved C и ограниченные исходными телами native ASM сохранены через `capture.py`; `verify.py` проверяет байты PE, ABI, поля и таблицы. Старый REVIEW с основаниями сохранён в `prior-review.txt`.

Обозначения: W — private object оружия, P=[W+160] — текущий владелец, V=[object+4] — native entvars, G=[10223188]. Все смещения hex. Перечитывания после callback существенны: этот код не обеспечивает lifetime/reentrancy safety. Float-ветви ниже описывают обычное исполнение с masked FP exceptions, а не гарантию отсутствия аппаратного исключения.

Native RTTI и vtable `CGlock@101b0524`: `13c→10045ac0`, `140→1011c020`, `144→100457d0`, `14c→10045b40`, `198→1011f5d0`, `19c→1011f640`, `1b0→10047db0`, `1c4→10047cf0`, `8→1011f680`. Последний — weapon clock scheduler, а не общий `1000e1f0`. `1011c1a0` вызывается прямо, принимает шесть stack arguments. Engine table base10222f48, initializer100b4aa0,144 DWORD; API имена сопоставлены с закреплённым eiface.h.

Native save descriptors подтверждают ITEM: W128=m_iSprintState, W140=m_iSuicideState, W148=m_iSuicideButtonsPressed; WEAPON: W178=m_bIronSights (тип12 в сериализации, но эти bodies читают/пишут BYTE), W19c=m_flCurrentKick, W1a0=m_flNextKickReductionTime. PLAYER P3f4=m_bFirstDeploy, count33/type12; здесь индексирование буквально BYTE по id, не stride4 из generic сериализатора. P5d0=m_iFlashlightFlags. ENTVARS save descriptors подтверждают V114=body, V1b4=max_health и V260=fuser3. V21c=weaponanim сопоставлено отдельно по закреплённому engine/progdefs.h и native animation sender1011f5d0; transient поле21c не входит в эту save table. Не переносить одинаковые численные offsets между W/P/V.

## 0x100457d0 — CGlock_DeployWithBodyAndFirstUse

ABI ECX=W, без stack arguments, plain RET. Все шесть конечных ветвей вызывают1011c1a0, затем POP ESI/RET сохраняют полный EAX helper (0/1), хотя Ghidra показывает void. До helper уже происходят записи и сообщения; его отказ не откатывает их. Нет начальных NULL/health/ammo/finite guards.

Если BYTE W200!=0, взять младший byte P5d0 и mask4: V.body114=1 при сброшенном mask,2 при установленном. Затем fresh vptr.virtual19c(current P,current body). Concrete1011f640 отправляет WeaponBody через MessageBegin(1,id,0,P.edict), BYTEbody,End при P!=NULL. После callback BYTE W200 перечитывается. Если теперь0 (или был0 на входе), fresh W.V.body проверяется: ненулевой body обнуляется и повторно посылается через virtual19c. Поэтому callback может вызвать в одном Deploy два body-сообщения. Этот body сам не меняет P5d0.

Сохранить clip W1e4 в EDX; W128=0; W140=(прежний W140==666) полным DWORD0/1. Clip==-666 заменяется0 и в памяти, и в EDX. Остальные отрицательные clip не нормализуются. Затем прочитать idW168 и P; если BYTE[P+3f4+id]==0, записать туда1 ДО вызова100f3d90(P,stringOffset("ironsights"),0). Native caller передаёт два DWORD; дальнейшая hint policy — support, его результат здесь не проверяется. Индекс не ограничен, и byte latch остаётся1 при подавленном hint или дальнейшем отказе Deploy.

Первое извлечение выбирает sequence29 (1dh), независимо от clip. При уже установленном byte latch используется сохранённый clip после обработки sentinel:0→sequence7, любой ненулевой→6. Во всех трёх случаях отдельно проверить global rules10222ee4; при ненулевом rules и ненулевом virtual20 выбрать player-model `police/models/weapons/glock/p_glock.mdl`, иначе `models/null.mdl`. Для подтверждённых CHalfLifeRules/CHalfLifeMultiplay slot20 возвращает0/1 соответственно; произвольные overrides остаются внешними.

Вызов1011c1a0(W,`models/weapons/glock/v_glock.mdl`,выбранный player-model,sequence,`onehanded`,0,0). Это шесть stack DWORD в порядке viewModel,playerModel,sequence,extension,animationArg2,animationArg3; callee RET18h. Helper вправе заменить viewModel по W16c. Свой selected clip для выбора sequence не перечитывается после rules callback. Дальнейший helper не выбирает заново initial sequence по текущему clip.

## 0x10045b40 — CGlock_HolsterAndCancelSuicideState

ABI ECX=W, no args, plain RET; нет нормализованного return status. Немедленно выбрать sequence9 при clip W1e4==0, иначе8 (включая отрицательный clip), вызвать fresh virtual198(sequence,1,0). Concrete1011f5d0 записывает player sequence и отправляет SVC35 BYTEsequence/BYTEbody, но два дополнительных arguments не использует. Здесь не проверяются deadlines, iron/reload flags или owner validity.

После animation перечитать W140. Только если он ненулевой: W78=0, W148=0, W140=0 в таком порядке; создать float RGB(128,128,128), вызвать10119c00(current P,&RGB,0.5f,0.0f,255,0). После fade перечитать P/V и сравнить V.fuser3 с10.0 через UCOMISS/LAHF/TEST: обнулить лишь ordered exact10, NaN и остальные значения оставить. Если W140 был0, W78/W148 и fuser3 эта ветвь вообще не меняет.

Независимо от suicide-ветви взять current P5d0; если mask4 установлен, записать прежний DWORD&~4, сохранив остальные bits, затем перечитать P. Никакого WeaponBody-сообщения или изменения W200 здесь нет. В конце прочитать fresh G.time, вычислить float32(double(now)+native double0.5), записать P308. Только этот player deadline меняется здесь; W1cc/W1d0/W1d8 не назначаются. Перенос нельзя заменить float32 сложением без доказательства эквивалентности на всех inputs.

## 0x10045ac0 — CGlock_WriteItemInfo

ABI ECX=W, один out-pointer, RET4, полный EAX=1. Без NULL/size checks записывает 11 DWORD в ItemInfo, одновременно W168=3. Native запись out18 получает W.V.classname+G.stringBase, а не постоянную строку weapon_glock; для alias/custom classname результат может отличаться. Указатели borrowed, память не выделяется.

Полная карта output: +00=4,+04=0,+08=pointer literal `glock`,+0c=150,+10=NULL,+14=-1,+18=classname pointer,+1c=15,+20=3,+24=0,+28=5. Native порядок:18,08,0c,10,14,1c,00,04,24,затем W168,20,28. Сопоставление ItemInfo: slot4/position0, primaryName glock/maxPrimary150, secondaryNameNULL/maxSecondary-1, name, maxClip15,id3,flags0,weight5. Эти имена сверены с прежним producer1011fb60, который после успешного virtual13c копирует все11DWORD в global table по id; сам текущий body глобальную таблицу не пишет. Возврат1 не проверяет корректность out, classname/string-base или prior registration.

## 0x10047db0 — CGlock_ScheduleTaclightToggle

ABI ECX=W, no args, plain RET; return EAX не общий bool. Один начальный snapshot G.time. Последовательные COMISS(deadline,now)/JA отсекают только ordered W1cc>now и W1d0>now; equality и masked NaN проходят. Затем нужны BYTE W200!=0,BYTE W178==0,DWORD W128==0,DWORD W140==0. W1d8, W1f0 reload и held/pressed button здесь не проверяются. Это literal vslot1b0, полный внешний input dispatch не выводится из названия действия.

При допуске clip==0 выбираетsequence18 (12h), иначе17 (11h), virtual198(sequence,1,0). Затем fresh virtual8(float0.3) — concrete CGlock target1011f680: clock1011ab20 через ST0 плюс float0.3, округление в float32, запись W58 и W.V.nextthink104,RET4. Это планирование оружия, не player scheduler. После scheduler вызывающий body устанавливает W78=10047cc0, потенциально заменяя прежний callback, без проверки очереди.

Затем fresh G.time расширяется в double, прибавляется native double0.66, округляется в float32; один результат последовательно пишется W1d8,W1d0,W1cc. Clock планирования и clock cooldown прочитаны отдельно. Callback10047cc0 только переключает mask4 в текущем P5d0, сохраняя остальные bits; не очищает W78, не отправляет WeaponBody сам и не повторяет eligibility guards. Обновление видимого body происходит в других frame/deploy путях; выполнение scheduler и порядок engine кадров здесь не наблюдались.

## 0x10047cf0 — CGlock_IdleByCurrentAnimationDuration

ABI ECX=W, no args, plain RET, без стабильного EAX status. До всех guards вызвать100dfea0(P,&localVector,raw float bits3db27eb6): native helper RET8 копирует G.forward в output и игнорирует второй argument и ECX. Local vector далее не используется. Это не autoaim/trace с восстановленным cone: нельзя добавлять в реконструкцию такую работу по SDK-сходству.

Fresh G.time и COMISS(W1d8,now)/JA: только ordered future deadline отсекается; masked NaN проходит. Затем W128==0 и W140==0. W178 BYTE и clip выбирают четыре sequences: iron0,clipnonzero→0; iron0,clip0→1; ironnonzero,clipnonzero→32; ironnonzero,clip0→33. Все ветви virtual198(sequence,1,0). Это отдельный duration idle callback1c4, не random idle100459b0(slot1d4). Общий frame1011d560 вызывает1c4 лишь при id11h на соответствующем tail; штатный id3 не доказывает вызов этого callback в каждом кадре.

После animation загрузить fresh P.V.weaponanim21c и PUSH его ДО engine GetModelPtr(W.V.edict). Этот оставшийся stack argument не принадлежит GetModelPtr: после caller ADD ESP,4 и PUSH header он становится вторым аргументом cdecl1000f390(header,savedWeaponAnim). Поэтому вычисляется длительность фактического player weaponanim после callback, не обязательно выбранного выше sequence. Model header принадлежит текущему weapon edict, не player edict. Helper возвращает ST0:0 при NULL header, signed sequence>=numseq или frames<=1, иначе float32((frames-1)/fps); отрицательный sequence и fps0/NaN не отсекаются.

Сохранив duration в ST0, загрузить fresh G.time, выполнить x87 FADD float(now), FSTPfloat32 в W1d8. Другие weapon/player deadlines не меняются. Native не вводит минимального положительного срока; zero duration даёт now, отрицательные/NaN values не исправляются. Изменения callback/engine global и model data остаются наблюдаемой границей; он не проверяет успешное воспроизведение анимации.

## 0x1011c1a0 — Weapon_DeployCompleteWithCustomTextureSync

ABI ECX=W, шесть stack DWORD `(viewModel*,playerModel*,sequence,extension*,animationArg2,animationArg3)`, RET18h. Полный EAX0 при virtual140()==0 либо последующем P==NULL; полный EAX1 после всех нормальных операций, без проверки результатов engine calls. CGlock virtual140=1011c020: возвращает0 только при ненулевом P и P.V.movetype==5, иначе1; NULL owner predicate допускает, но текущий helper затем отвергает. После успешного predicate clip==-666 нормализуется0 ДО owner NULL guard. До этого helper никаких собственных writes не делает, хотя predicate может иметь side effects.

Прежний texture-контракт сохранён целиком: при BYTE P3a9==0 сначала поставить1; затем проверить world10223190. При NULL world отправки не будет, latch остаётся1. Каждый ненулевой world+f0/+f4/+f8 отправляется current owner через MessageBegin(1,CustomSlv/CustomFng/CustomGlv,0,P.edict), WriteString(G.stringBase+worldOffset),End. Нулевое поле не отправляет reset. Между отправками world перечитывается и проверяется; внутри начатой отправки после MessageBegin world и поле перечитываются БЕЗ повторной NULL проверки. Никакого length limit, filename conversion, rollback или retry здесь нет. Повторный Deploy пропускает этот блок, пока внешний writer не сбросит P3a9; источник глобальных offsets и клиентский renderer остаются отдельными contracts.

Выбрать viewModel в EBX: при W16c!=0 сохранить G.stringBase+W16c и AlertMessage(1,"Setting custom v model: %s\n",pointer), иначе исходный arg1. Это сохранённый pointer, не повторное чтение W16c после сообщений. Далее BYTE W178=0; W1a0 получает raw DWORD свежего G.time; W19c=0. Отправить WpnDeploy(idglobal10226664), destination8, recipient current P.edict, payload0 bytes. Нельзя подменять destination8 единицей или добавлять BYTE id: native вызывает Begin/End без writes; registry фиксирует размер0.

Если W120 отличается от signed/raw reserve DWORD P[2540+4*W1dc], отправить WpnInfo(idglobal102265b8), destination1, current P.edict: BYTE W168, BYTE `[102318a4+44*W168]`, SHORT current reserve,End. Второе поле — native ItemInfo maxClip (+1c при table base10231888), не ammo-type. После End заново загрузить P и W1dc, прочитать reserve и сохранить в W120; при callback-изменении это может отличаться от уже отправленного значения. Если начальное сравнение равно, сообщения и записи W120 нет. Индексы, signed ranges и потеря старших bits на wire локально не ограничиваются. WpnInfo native payload4 bytes; global id — runtime результат регистрации, не число адреса.

Всегда вызвать RandomLong(-5,5), сохранить wrapping32 result+100 как pitch. Затем проверить W.V.max_health1b4: только ordered exact1.0 обнуляет это поле и пропускает sleeve sound; NaN/любое другое значение идут в sound branch. Таким образом RNG pitch потребляется даже при подавленном звуке. Во второй ветви RandomLong(0,2):0→weapons/sleeve_generic1.wav,1→...2.wav,2→...3.wav, иное→без звука. EmitSound wrapper100fc9f0(current P.edict,channel0,sample,1.0f,0.8f,flags0,pitch). Это weapon max_health, не HP игрока; причина установки sentinel внешняя. Обёртка может применять собственную глобальную громкость/sentence policy; здесь нет проверки её результата.

После sound/suppression вызвать100f5eb0(current P) для синхронизации ammo mirrors. Затем fresh P.V.viewmodelBC=сохранённый viewModel−fresh G.stringBase; отдельно P.V.weaponmodelC0=arg2−fresh G.stringBase. Следом скопировать arg4 extension побайтно вместе с NUL в current P+2678; нет NULL/length/buffer guard, overlapping-copy гарантии или allocation. Native не использует AllocString для этих двух offsets. Каждый owner/base загружается в указанном порядке, а не единым snapshot на весь helper.

Затем fresh vptr.virtual198(arg3,arg5,arg6); конкретный sender1011f5d0 использует sequence, игнорирует два последних arguments и RET0c. После callback engine SetModel(current W.V.edict,сохранённый viewModel), затем10120210(W,сохранённый arg3), затем EAX1. В этом SetModel используется weapon edict и viewmodel filename, не world model из Spawn. Helper10120210 получает model duration выбранного sequence после SetModel, назначает P308, копирует его в W1cc/W1d0, а W1d8 вычисляет через отдельное чтение clock. Длительность не является fixed0.5 и не передана отдельным аргументом Deploy. W1f0 reload flag и W78 callback здесь не очищаются; они не должны добавляться в реконструкцию по ожиданию SDK.

## Границы и дальнейшая навигация

Полные локальные ветви шести primary закрыты; support-функции не получают новых REVIEW автоматически. Общий helper сохраняет весь прежний texture evidence, а новая карточка расширяет его до weapon state/messages/models/sound/timing. [Frame](../server-glock-frame/contract.md), [атаки](../server-glock-attacks/contract.md), [другие действия](../server-glock-actions/contract.md), [вход в прицел](../server-glock-iron-entry/contract.md) и [WeaponMelee](../server-weapon-melee/contract.md) дают продолжение.

Остаются отдельными границами concrete client обработчики WpnDeploy/WpnInfo/WeaponBody, реальные модели и последовательности, точные external callbacks и runtime frame order. Отсутствие вызова idle1c4 при штатном id3 в одном общем frame не доказывает отсутствие всех других callers. Native descriptor type12 не разрешает менять BYTE ABI на generic DWORD strides. Цель пакета — воспроизводимые исходные contracts, а не исправление потенциально небезопасного оригинального кода.
