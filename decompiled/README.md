# Декомпил Cry of Fear

Здесь собраны сохранённые результаты Ghidra в виде C-подобного
псевдокода. Это частичный декомпил бинарников, а не исходники разработчиков
и не готовый к сборке проект. Имена, типы и структуры могут быть восстановлены
неточно; служебные типы Ghidra требуют дальнейшего разбора.

## Каталог функций

[`FUNCTION_CATALOG.txt`](FUNCTION_CATALOG.txt) — единый каталог на русском:
назначение разобранных функций, адреса, сигнатуры, ссылки на каждый `.c`,
строки и ресурсы, видимые вызовы, vtable-классы и очередь дальнейшего разбора.
Подробные статические разборы отделены от автоматической описи и неизвестных
назначений. Это рабочая карта восстановления, а не заявление о полном понимании
игры или совместимости её новой реализации.

Текущая работа — только реверс: доказательства поведения, владельцы данных,
цепочки вызовов и открытые вопросы. Перенос в игру сейчас не выполняется.

Начните со сводки `SECTION progress`, затем с оглавления:
карта механик → краткий индекс → полная карточка → исходные доказательства.
Текущие числа по DLL автоматически записываются в
[`PROGRESS.json`](PROGRESS.json) тем же запуском генератора. Поле
`catalog_sha256` позволяет проверить, что JSON соответствует версии каталога.
Число записей без REVIEW — остаток ручного разбора **сохранённого корпуса**,
а не всех функций игры; наличие REVIEW также не означает полного раскрытия.
Полное число ещё не выгруженных функций неизвестно.
Номера строк пересчитываются при генерации. В начале файла также есть шаблон
контракта функции и блок `WORKBOARD` для текущей задачи, реализации и проверок.
Разобранные функции размещены перед остальной технической описью.

Быстрое чтение без перегенерации:

```text
python tools/catalog_decompiled.py --find inventory --limit 12
python tools/catalog_decompiled.py --show server:0x100e4410
python tools/catalog_decompiled.py --mechanic doors
python tools/catalog_decompiled.py --mechanic movement
python tools/catalog_decompiled.py --mechanic vitals
python tools/catalog_decompiled.py --mechanic ladders
python tools/catalog_decompiled.py --section workboard
python tools/catalog_decompiled.py --section progress
```

Обновить опись можно командой `python tools/catalog_decompiled.py` из корня
репозитория. Ручные заметки находятся в блоках `[REVIEW ...]` и `[WORKBOARD]`
самого текстового каталога и сохраняются при обновлении. Генератор проверяет контрольные суммы
исходных файлов и заменяет каталог только после успешной записи нового файла.

## Содержимое

| Папка | Модуль |
| --- | --- |
| `server/captures/` | `hl.dll` — выборочные captures |
| `server/partial-pass/functions/` | `hl.dll` — остановленный общий проход |
| `client/captures/` | `client.dll` |
| `gameui/captures/` | `GameUI.dll` |
| `engine/captures/` | `hw.dll` |
| `opengl/captures/` | `opengl32.dll` |
| `vgui2/captures/` | `vgui2.dll` |

Прежние выборки разложены по именам сеансов анализа. В каждом `capture.json`
есть адреса процедур, SHA-256 бинарника и файлов, идентификаторы исходных
свидетельств и путь к локальному сеансу. Исходные `.c` скопированы без изменений.

В `server/partial-pass/index.json` перечислены адреса, имена и контрольные
суммы 8 000 сохранённых функций из 10 398 выбранных Ghidra. Проход остановлен
по просьбе пользователя; остальные функции не включены именно в тот проход.
Отдельные последующие captures могут содержать часть из них. Выборки могут
пересекаться между собой и с общим проходом: число файлов не равно числу
уникальных функций. `inventory.json` — исторический снимок первоначальной
импортированной описи, не текущая сводка. Актуальные числа находятся только
в генерируемых `SECTION progress` и `PROGRESS.json`; полный объём игры из
размера выбранной серверной выборки не выводится.

Оригинальные DLL и игровые ресурсы сюда не включены и не изменены.
Разбор движения, бега, прыжка, стамины, HP и двух видов лестниц собран в
карточках справочника; краткий маршрут и доказательства —
[`analysis/movement/overview.md`](../analysis/movement/overview.md).
Рабочие базы, журналы и полные локальные свидетельства остаются в
игнорируемой Git папке `analysis/local/`. Настройка инструментов описана в
[`analysis/native-toolchain.md`](../analysis/native-toolchain.md).
